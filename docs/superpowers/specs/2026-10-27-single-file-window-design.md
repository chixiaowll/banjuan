# 单文件窗口（像 VS Code 那样直接打开一个文件）— 设计

日期：2026-10-27
状态：已与用户确认（入口与窗口 / 查看 / Markdown 编辑与保存 / 加入书库与范围）；实现计划见 docs/superpowers/plans/2026-10-27-single-file-window.md

## 背景与目标

现在看任何文件都必须先把它放进书库：应用没有登记任何文件类型，也不处理“从访达打开文件”，各个阅读器都依赖书库（批注、阅读进度、读文件的权限都按书库来）。

目标：像 VS Code 不打开工作区时那样，直接打开某一个文件查看；Markdown / 纯文本还能直接编辑并保存回原文件。不在任何书库里留下东西；想批注、做笔记时一键加入书库。

不做：iPad（本来就从“文件”App 打开）；不进书库的批注；把 Markdown 导入为笔记。

## 1. 入口与窗口

三个入口进入同一种“单文件窗口”：

1. **访达**：把 PDF、EPUB、Markdown（`.md` `.markdown`）、纯文本（`.txt`）、图片、网页（`.html` `.htm`）登记为可以用半卷打开（角色 Viewer / Editor，不抢系统默认程序，用户可自行设为默认）。双击（设为默认后）、右键“打开方式 → 半卷”、拖到 Dock 图标，都走 macOS 的 `open-file` 事件；应用未启动时同样生效（启动早期收到的事件先排队）。
2. **命令行**：`banjuan <文件路径>`。应用没开时先启动它，再通过本地接口（带令牌的 `POST /api/view`，参数为绝对路径）交给它打开。参数与已有子命令同名时子命令优先（如要打开名为 `list` 的文件，写 `./list`）。
   应用的启动参数里带的文件路径也会打开：跳过 Electron 自身的参数和应用脚本路径，取其余参数中真实存在的文件。这也是端到端测试的入口。
3. **应用菜单**：文件 → 打开文件…（⌘O）。

窗口行为：

- 每个文件一个独立窗口，标题是文件名；没有书库选择、标签栏、书库侧栏。
- 同一个文件（按真实路径判断）再次打开时，把已有窗口拿到前面，不重复开。
- 因为打开文件而启动应用时，只开这个文件的窗口，不再弹出书库/欢迎窗口。
- 文件位于某个已知书库之内时（按真实路径判断，书库列表取书库历史记录），顶部提示“在书库「XX」中”，提供“在书库中打开”。在单文件窗口里编辑这样的 Markdown 同样生效：书库里看到的就是改后的内容。
- 单文件窗口跟随应用的主题和语言设置。
- 关窗口、退出应用前，单文件窗口和书库窗口一样，先把未写完的内容写完（第 3 节）。

## 2. 查看 PDF / EPUB / 图片 / 网页

复用现有阅读器（`DocumentViewer` 及各类型阅读器）。

- **保留**：缩放、目录 / 缩略图、⌘F 文内搜索、复制文字、护眼 / 墨水屏模式；EPUB 字号与章节跳转。
- **隐藏**：高亮 / 下划线 / 墨迹 / 区域批注工具、批注侧栏、关联笔记侧栏、标签、阅读计时；选中文字的浮动工具条只留“复制”。
- **阅读位置**：按文件真实路径记在本机应用数据目录的 `file-view-state.json` 里（与书库无关、不同步），只保留最近 500 个文件，下次打开回到上次位置。不向被打开的文件写入任何东西。
- **大文件**：同样走分段读取（`fileSize` / `readFileRange` + pdf.js 分页存储），2GB 以上的 PDF 也能打开。
- **网页（HTML）**：只看不改，按网页显示。脚本一律不执行（显示框架不放行脚本）；按页面声明的字符集解码（GBK 等老网页不乱码）；页面里相对路径引用的样式表、图片、字体可以加载，为此只放行该网页所在文件夹（含子文件夹）里的这几类文件，脚本和其他网页不放行。加入书库时只复制网页文件本身，书库里显示时不带它旁边的样式和图片。
- **不支持的格式**：不登记到“打开方式”；若从命令行传入，显示“半卷不能查看这种文件”，并提供用系统默认应用打开。

实现要点：

- 渲染端：新的窗口入口（与导出 worker 一样用 URL hash 区分），为这个文件提供一套只服务它的 `BanjuanAPI` 实现：`documents.get` 返回由文件生成的文档信息；读文件类接口只读这一个文件；`documents.update` 只用于记阅读位置；批注类返回空 / 不可用。
- 阅读器通过一个“单文件模式”上下文开关隐藏上面列出的工具，书库窗口不受影响。
- 主进程：记录“窗口 → 它打开的文件”；单文件相关的 IPC 只放行该窗口自己的文件。`local-file` 协议额外放行用户打开的文件（以及第 3 节所述同目录图片、上面所述网页同目录的样式表 / 图片 / 字体）。网页通过 `<base href="local-file:///所在文件夹/">` 让相对链接落到这些文件上。

## 3. Markdown / 纯文本的编辑与保存

- **编辑器**：CodeMirror 6（项目已依赖，流程图编辑器在用），Markdown 语法高亮、自动换行、撤销重做、⌘F 查找替换。原文按字节保留：缩进、空行、列表符号、换行符（LF / CRLF）、BOM 都不改。
- **预览**：默认显示源码；工具栏“预览”按钮切换为左编辑、右实时预览（`.txt` 无预览）。预览用书库里显示 Markdown 文档的同一套渲染。相对路径引用的图片可以显示，为此只放行该文件所在文件夹（含子文件夹）里的图片类文件。
- **保存**：自动保存（停止输入约 1 秒后写回原文件），⌘S 立即保存，标题栏显示“已保存 / 未保存”。写入采用“先写临时文件再替换”。关窗口、退出应用前通过现有 flush 机制先写完。
- **保护原文件**：
  - 不是合法 UTF-8 的文件（如 GBK）只读打开，并说明原因。
  - 监视文件：外部修改时，若无未保存修改则自动载入；若有，则提示“载入外部修改 / 保留我的修改”。
  - 文件在打开期间被删除或移走：提示，并暂停自动保存（不在原位置悄悄重建文件）。

## 4. 加入书库

- 单文件窗口的“加入书库”按钮：选择目标书库（最近用过的书库，默认上次用的），把文件**复制**到书库根目录（重名为“name (2)”），原文件不动，之后两份互不影响。
- 加入后在书库窗口打开该文档（书库已在某窗口打开则切过去，否则新开窗口），单文件窗口关闭。
- Markdown 也作为“文档”加入。
- 文件本来就在某个书库内时，按钮为“在书库中打开”。
- 一个书库都还没有时，按钮不可点，悬停提示“还没有书库”。

## 测试

- 单元测试：
  - 单文件接口只放行该窗口打开的文件
  - 阅读位置的记录与读取
  - 非 UTF-8 判定
  - 原子写入
  - 外部修改检测与提示条件
  - 同一文件不重复开窗口
- 端到端测试（启动参数带文件路径打开应用，与访达 / 命令行同一路径）：
  - PDF 能看且批注工具不出现
  - 2GB 以上 PDF 能打开
  - Markdown 编辑后自动保存回原文件且原文格式不变
  - 外部修改被载入
  - 加入书库后原文件不变、书库多一份
  - 同一文件不重复开窗口
- 所有新文案补齐 7 种语言。
