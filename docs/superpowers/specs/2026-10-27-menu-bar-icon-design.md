# 菜单栏图标与“在 Dock 中显示”开关 设计

日期：2026-10-27　分支：`feat/menu-bar-icon`（基于 `feat/single-file-window`）

## 目标

半卷在 macOS 菜单栏（屏幕右上角那排状态图标）常驻一个图标；设置里可以关掉 Dock 图标，让半卷只待在菜单栏里。关掉所有窗口后半卷本来就在后台运行（截图快捷键、本地接口照常可用），菜单栏图标给它一个随时可点的入口。

只做 macOS。Windows / Linux 行为不变（关掉最后一个窗口即退出，不加托盘图标）。

## 1. 菜单栏图标

- 一直显示，不受 Dock 开关影响——Dock 图标关掉后它是唯一入口。
- 图案：应用图标的轮廓（五根竖条 + 两道横线，横线与竖条交叉处留缝），做成单色模板图（`trayTemplate.png` / `trayTemplate@2x.png`，放在 `packages/app/resources/`），随系统深浅色自动变色。
- 左键或右键点击弹出系统原生菜单，每次弹出时按当前状态现做：

  | 菜单项 | 动作 |
  |---|---|
  | 打开半卷 | 有书库 / 文件窗口就全部调到最前；一个都没有就开书库窗口（同点 Dock 图标） |
  | 截图（右侧显示当前截图快捷键） | 开始截图 |
  | 打开文件… | 同“文件 › 打开文件…” |
  | ── | |
  | ✓ 在 Dock 中显示 | 切换开关 |
  | ── | |
  | 退出半卷 | 退出（照常先写完未保存内容） |

- 菜单文字跟随应用语言（7 种语言，键加在 shared-ui 的各语言文件里，主进程直接读这些文件）。渲染端在语言确定和切换时告诉主进程，主进程记进设置文件；还没有窗口报告过时，按系统首选语言选，规则同渲染端。

## 2. 「在 Dock 中显示」开关

- 位置：设置面板“截图快捷键”下面一行勾选开关，默认开；只在 macOS 显示（preload 只在 macOS 提供这组接口）。
- 与菜单栏菜单里的勾选项双向同步：主进程是唯一来源，改动后广播给所有窗口，开着的设置面板跟着变。
- 保存在 `~/.banjuan/settings.json`（`showInDock`，缺省为开），与截图快捷键同一文件。
- 关掉：`app.dock.hide()`。Dock 和 ⌘Tab 里都没有半卷；已开的窗口留在原处。半卷窗口在前台时屏幕顶部也不显示“文件 / 编辑…”菜单（macOS 对不在 Dock 里的应用的统一规定），但菜单仍在，⌘C / ⌘V / ⌘O / ⌘W 等快捷键照常可用（实测确认）。
- 打开：`app.dock.show()`，恢复原样。
- 关着开关启动时，Dock 图标会先闪一下再消失（Info.plist 未设 `LSUIElement`）。完全不闪需改成默认不进 Dock、再按需显示，副作用更多，不做。

## 3. 实现要点

- `packages/app/src/main/menu-bar.ts`：创建菜单栏图标，点击时现做菜单；菜单内容由纯函数 `trayMenuItems(state, actions)` 生成（状态：语言、Dock 开关、截图快捷键），便于测试；Dock 显示 / 隐藏与 IPC（读、写开关，上报语言）。
- `settings-store.ts`：加 `showInDock`、`locale` 的读写。
- `windows.ts`：加“把所有书库 / 文件窗口调到最前，没有则返回 false”的函数。
- preload / `BanjuanAPI`：可选的 `menuBar` 接口（仅 macOS）：读写开关、监听变化、上报语言。
- 渲染端：设置面板新的一行组件；应用根组件里上报当前语言。

## 4. 测试

- 单测：菜单项生成（各语言文字、勾选状态、快捷键显示、各项动作）；语言选择规则。
- 实测（隔离的 HOME 与 `--user-data-dir`）：
  - 切换开关后用 `lsappinfo` 确认应用类型在 Foreground / UIElement 之间切换，`settings.json` 写入，设置面板与菜单同步；
  - 关着开关重启，启动后不在 Dock；
  - Dock 隐藏时，用系统按键事件确认 ⌘C / ⌘V、⌘O 仍然有效；
  - 截菜单栏的图，确认图标显示正常。
